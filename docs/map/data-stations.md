# Station data: Ikebukuro and Shinjuku

## What it does

Each station ships its shared-contract files under `stations/<id>/gteki/`: `station.json` (frame, floors, coverage, spawn), `graph.json` (walk graph), `pois.json` (gates, exits, platforms, stores, shops) and `tenants.json` (department-store directory rows, not POIs). The app, search and scene read only these committed files. Raw source data never enters Git; the generators read it from a directory outside the repo.

The two stations are built differently:

- **Shinjuku** is generated by TypeScript from the MLIT ほこナビ E-27 (Toei Shinjuku) dataset: `import:e27` writes `station.json`, `graph.json`, `pois.json` and the render plan `stations/shinjuku/data/plan.json`; `bake:surface` then bakes the street layer into `stations/shinjuku/data/surface-baked.json` from committed files only.
- **Ikebukuro** is built by the Python pipeline from the PLATEAU underground GML (`build:data`), with hand-authored graph input `stations/ikebukuro/data/graph.src.json`. Field receipts are applied by a separate TS step.

## Data flow

```
Shinjuku:  fetch-sources.sh → $GTEKI_RAW_SHINJUKU (~/Developer/gteki-raw/shinjuku, 566 MB)
           → import:e27 (+ docs/research/field/receipts) → gteki/{station,graph,pois}.json + data/plan.json
           → bake:surface → data/surface-baked.json → scene / app / search
Ikebukuro: fetch_sources.sh → data-cache/ikebukuro/*.gml
           → build:data (extract → Blender GLB → build_station/signage/walkfix/access/anchors)
           → gteki/*.json + assets ; import_field_receipt.ts <receipt> patches them afterwards
```

POIs from research (lines, stores, shops) are added by the generators from contract JSON in `docs/research/lines/*-line-pois*.json` and `docs/research/merchants/`; they are **search-only** (no `floorId`, `position` or connectors) until a field receipt or a routed source ties them to a node. A store connector may come **only** from a field receipt (`import-e27.ts` throws otherwise).

## Tests CI runs and regenerating data

Run from the worktree root. Tests always go through `orb-test` (OrbStack container, worktree copied to /w); never on the host.

```sh
# Shinjuku regenerate (needs raw data)
pnpm --filter @gteki/station-shinjuku import:e27            # write
pnpm --filter @gteki/station-shinjuku import:e27 --check    # fail if outputs would change
pnpm --filter ./stations/shinjuku bake:surface              # ALWAYS after import:e27 or any station.json edit
pnpm --filter ./stations/shinjuku bake:surface -- --check

# Ikebukuro receipt import
pnpm exec tsx stations/ikebukuro/pipeline/import_field_receipt.ts docs/research/field/receipts/<date>-ikebukuro.json

# Station tests in a container (Shinjuku needs 3g; 2g OOMs)
orb-test --memory 3g -- pnpm vitest run stations/shinjuku
orb-test -- pnpm vitest run stations/ikebukuro apps/web/src/search-stations.test.ts

# Full root set, as CI runs it (heavy: queues for the host-wide lock)
orb-test --heavy -- sh -c 'pnpm typecheck && pnpm vitest run --maxWorkers=2'
```

**Raw data in orb-test.** The container has no ~/Developer/gteki-raw. For a raw-dependent run, copy the raw dir into the worktree (e.g. .review/raw), pass `--env GTEKI_RAW_SHINJUKU=/w/.review/raw`, and **delete .review afterwards** (one-off data rule). .review must never be committed. Ikebukuro's frame check uses `GTEKI_UBLD_ENU=<build/ubld_enu.json>` the same way; without it that block is skipped.

## Pitfalls

- **A `station.json` edit is not done until `bake:surface` is re-run** and surface-bake, kit-swap and scene-digest tests pass: `surface-baked.json` pins the station bytes. #549 went red in CI because this was missed.
- **Add the app search tests** when POIs change: `apps/web/src/search-stations.test.ts` asserts result lists (#509 broke on new exit POIs).
- Sign text uses a bundled font: a new glyph (e.g. ㈱ in #538) fails the root sign tests.
- E-27 swaps `route_type` 5/6 relative to the spec, has no fare attribute and no elevations; heights are symbolic. Read the `import-e27.ts` header before changing derivation.
- Search-only POI counts appear in tests (e.g. 493 → 494 after #538); a merge that crosses another POI PR must regenerate, not hand-merge JSON.
- Container clock is UTC; label times before reporting.

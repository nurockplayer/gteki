# DR-new-3d-indoor-sources: discovery of public 3D / indoor / underground / point-cloud sources not yet in the dossier or sources.yaml (tracking issue #165, item R9)

## 1. Header

- **Gap refs:** tracking #165 item R9. M0-01 ranks 2, 3 and 6 are the context: rank 2 and 3 are the missing indoor/underground geometry and graph for Ikebukuro and Shinjuku (IK-04, IK-07, SJ-04, SJ-07), and rank 6 is the heights question (IK-15, SJ-20). Rank 5 (SJ-07, MLIT R2) and rank 15 (IK-06, R1) are touched where a new fact bears on them. This file does not repeat DR-rights-lineage (R5).
- **Checked:** 2026-10-22 (JST, 16:00 to 17:00). Author: R9 research worker. Desk research only. No browser was used.
- **Method:** WebSearch and WebFetch for pages; plain `curl` GET of public, unauthenticated CKAN `package_list` / `package_show` / `package_search` JSON (geospatial.jp, catalog.data.metro.tokyo.lg.jp, ckan.hokonavi.go.jp, data.e-gov.go.jp, search.ckan.jp) and HEAD requests; `pdftotext` on three PDFs that WebFetch had cached; one image-only PDF viewed. Repo files were read read-only (M0-01 matrices, dossier, `sources.yaml` ids, R5/R2 gap notes) to avoid re-reporting.
- **Footprint disclosure:** JSON files saved under `.../scratchpad/dl-r9/<own subdir>/` (each subdir new; largest: geospatial `package_list` 369,330 B; Tokyo catalog search results about 1 MB each; e-Gov `package_show` 300,200 B; all under 5 MB). **No data file was downloaded** (no ZIP, LAS, GeoJSON, CSV or shapefile saved by me). Four tiny CSVs (Toei station basics 11,405 B; Toei barrier-free list 5,142 B; two Shinjuku ward lists 7 KB and 29 KB) were read through the WebFetch tool only; WebFetch cached two of them as binary in its own tool-results folder. One WebFetch also followed a CKAN resource link that answered 302 to a pre-signed storage URL; the signed URL was not fetched (the tool refused). HEAD requests to signed URLs returned 403 (not retried). No one was contacted; no account, no API key, no login.
- **Known limits of the tooling:** the geospatial.jp CKAN `package_search` returned 0 hits for every query including known datasets (search backend not usable through the API), so discovery used the full `package_list` (17,310 package names, name scan only) plus `package_show` of specific ids plus the cross-catalog search `search.ckan.jp/backend/api/package_search`. The Tokyo public-transport challenge CKAN (`ckan-tokyochallenge.odpt.org`) timed out / returned 502 during the whole session.
- **Status vocabulary:** DISCOVERED = existence seen in a listing; PAGE_READ = landing page or raw CKAN JSON read; FILE_INSPECTED = a document or table body read. Existence of a dataset is not coverage, coverage is not routability. Unknown stays UNKNOWN.

## 3. Findings (facts only)

### 3.1 Tokyo point clouds: airborne yes, underground not published for these stations

- Tokyo's 区部 airborne LiDAR dataset (東京都デジタルツイン実現プロジェクト 区部点群データ) is on G空間情報センター as `tokyopc-23ku-2024`: 「航空レーザ測量により取得し、統合された16点/平方m以上の高密度点群データ」, 1/500 map-sheet ZIPs, JGD2011 plane rectangular zone IX; measured 2023-03 to 2023-04; CKAN license CC BY 4.0; metadata created 2024-08-15, modified 2026-02-04; press release 2024-10-31 says commercial, academic and personal use are all allowed. Resources: index ZIP (about 64 MB), LAS (original DSM and ground DEM), DEM GeoTIFF 0.25 m and 0.50 m, 1 m contours (DXF), simple ortho GeoTIFF, red relief maps 0.25 m and 0.5 m. The page warns an average file is about 200 MB and the largest about 400 MB, and that outliers may remain. Vertical datum is not stated on the page. The dataset covers the 23 wards, which include both stations' surroundings; per-sheet coverage was not checked. It is ground and building-top data, not underground. [DR-NS-01]
- Tokyo's 3D-viewer page (2026-09-25 snapshot) lists, under 3D city models, 「地下街」 models and says footpath, facility, vegetation and underground-mall models exist "only for some municipalities". It names no station and no download for them; 池袋 and 新宿 are not mentioned on the page. [DR-NS-03]
- The only underground **point cloud** found published by Tokyo is Toei Oedo 都庁前 (E28): 「地下3階（ホーム階）から地下1階までの一部」, LAS and PLY, LiDAR SLAM, partner ルーチェサーチ, press release 2021-03-02, published on G空間情報センター at `tochomae-3d-pointcloud`. That URL now returns HTTP 404, and no package name containing "tocho" is in today's geospatial.jp `package_list`. The Tokyo catalog has no 都庁前 3D entry (search "都庁前", "3D点群", "LiDAR", "ルーチェサーチ" returned no such dataset). Licence was never stated on the press page. It is not 新宿 (E27/E01) and not 池袋. [DR-NS-02]
- I found **no** Tokyo publication of the raw or processed 2023 LidarSLAM underground point cloud that fed the PLATEAU `ubld` models. Checked: the Tokyo open-data catalog (queries 地下, 地下街, 地下通路, 点群, 3D点群, LiDAR, 屋内, 新宿駅, 池袋駅, デジタルツイン), the geospatial.jp package-name list (no name with ikebukuro, toshima station, shinjuku point cloud), the cross-catalog search (queries 池袋, 新宿駅, 屋内地図, 地下街, 点群 駅, BIM 駅, IFC, 駅構内図, 歩行空間ネットワーク), the Tokyo 3D map requirement document chapter 3 (text-extracted: it describes SLAM only as a general survey technique and says nothing about publishing underground point clouds), and the 2024-03-29 press page for the ward 3D map data (no mention of 地下街 at all). This is a negative result of this search, not proof of absence. [DR-NS-01, DR-NS-02, DR-NS-04]
- Tokyo's 建設局 「ICT活用工事3D点群データ」 (43 resources; LAS files named for river, road and park works, plus 築地 depot) was listed: none of the visible resource names is in either station area (one is 富久町 street works). Negative. [DR-NS-20]

### 3.2 Tokyo catalog and the PLATEAU 2025 packages

- Tokyo's catalog entry 「都市の３Dデジタルマップデータ（区部・多摩部）」 (東京都都市整備局, license CC-BY-4.0, created 2024-03-29, modified 2026-03-27, 53 resources) says the data was "令和７年度に都で整備した" and its resources are the geospatial.jp packages, including `plateau-13104-shinjuku-ku-2025` and `plateau-13116-toshima-ku-2025` (format cityGML). It is a second, Tokyo-published licence statement for the same packages the GIS lane already uses; it does not say whether the catalog-API ZIPs are the same files (the R5 identity gap stands). The Shinjuku 2025 package notes (modified 2026-04-03) still mention an underground model at LOD1 and LOD4.1, spec 5.0, quality "map information level 2500". [DR-NS-04]
- No 2026-vintage `ubld` or ward package exists for 13104 or 13116 in the geospatial.jp package list (only `-2023` and `-2025` names). PLATEAUビジョン2026 (2026-07-17) was found only through search summaries and announces AI-based model generation, with no station or underground data release. [DR-NS-04, DR-NS-14]

### 3.3 MLIT indoor maps (高精度測位社会プロジェクト): Ikebukuro is not among them

- MLIT's own page lists five published indoor maps: 東京駅周辺 (`mlit-indoor-tokyo-r2`), 新宿駅周辺 (`mlit-indoor-shinjuku-r2`), 横浜国際総合競技場, 新横浜駅, 成田空港 (`-r2`). Ikebukuro does not appear anywhere on the page. Beacon open data was withdrawn after FY2021 (「令和３年度までオープンデータとして公開していました」). [DR-NS-11]
- Scanning the whole geospatial.jp package list gives the same set plus older vintages: `mlit-indoor-shinjuku` (平成29年3月暫定版, published 2017-11-16), `mlit-indoor-shinjuku-h30` (平成30年3月仕様版, 2018-11-12), `mlit-indoor-shinjuku-r2` (2020-10-27), `mlit-indoor-tokyo` and `-tokyo-r2`, `mlit-indoor-narita-airport(-r2)`, `-shin-yokohama`, `-yokohama-arena`, plus Nagoya city's own `city-nagoya-indoor-unimall` and `-centralpark`. No other 池袋 or 新宿 indoor-map package name exists. All three Shinjuku packages are 政府標準利用規約 (ogl), each has a 利用規約 PDF resource, and each says "ダウンロードは、ユーザ登録の後、ログイン状態で". Metadata modified 2024-10-05. The H29 and H30 vintages are older versions of the same area, superseded by R2 in the package notes. [DR-NS-11]
- MLIT's FY2019 first-meeting document (「令和２年度高精度測位社会プロジェクト 第一回検討会資料」, dated 2020-12) says that in FY2019 a **池袋駅屋内電子地図** was newly made "by a private company" (民間主体), from base maps held by ゼンリン and JR東日本コンサルタンツ, converted by NTTデータ to the GSI hierarchical indoor spec, and that "池袋駅屋内電子地図は、民間会社より東京公共交通オープンデータチャレンジに提供". It is not in the G空間 list. The 3rd Tokyo challenge's terms say data is for the contest only, commercial use is prohibited, no third-party provision, and the data "is planned to be available until the challenge ends" (implementation period 2019-01-16 to 2020-03-31; submissions closed). The challenge CKAN (`ckan-tokyochallenge.odpt.org`) could not be reached to see whether the file is still listed. Net: a floor-level Ikebukuro indoor map exists (or existed) but there is no public, reusable copy found. [DR-NS-12, DR-NS-13]

## 3. Findings (facts only)

### 3.1 GSI approval 令7関公第296号 and downstream use (rank 12; IK-03 / SJ-03)

- Repo baseline: the number appears in the PLATEAU resource lineage as 国土基本情報（2025年度）（国土地理院長承認（使用）令7関公第296号）, the source of `tran:function` / TrafficArea; the Owner accepted risk (b) (geometry only, approval read as attribute-scoped), which is "not an upgraded rights verdict". [DOS:G3; docs/gis/decisions/2026-10-22-plateau-tran-geometry-risk-acceptance.md]
- GSI's 利用手続 page says a 測量法 Article 29 (複製) or 30 (使用) application is needed in some cases, and that for others "出典の明示だけ" suffices; the procedure was revised in December 2019. [DR-RL-01]
- The 国土基本情報 product page (最終更新日 2026年7月31日) says that anyone who reproduces or uses the data "測量法第29条又は30条に基づく申請が必要になります"; it contains no attribution wording and no terms for redistribution. [DR-RL-04]
- Q1-24 (二次利用): "承認を得た成果品の利用については、前提として承認を得た者からの許諾が必要です。" It adds that for a **使用承認** product, further reproduction or use needs no application, while for a **複製承認** product an application "may be needed" (follow GSI's 利用手続フロー PDF). [DR-RL-02, verified in raw page text]
- Q1-25 (増刷): reprints "引き続き承認番号を明示することにより申請不要". [DR-RL-02]
- Q5-2 (表示): "承認書に記載される承認番号及び出所の明示の文言については、必ず明示しなければなりません。" For systems and websites the notice must stay visible while the map is displayed. [DR-RL-02, verified]
- The wording is therefore **per 承認書**; GSI's Q&A does not print a template. GSI's 出典の記載例 page gives only 出典 examples (e.g. 「電子地形図25000（国土地理院）を加工して作成」, 「地理院タイルに○○を追記して掲載」), not approval-number wording. [DR-RL-03; page read via WebFetch, not raw-verified]
- Q1-15: edited or processed material must not be presented as if GSI made it. Q1-16: if the GSI product is processed without being reproduced, "複製を行わない場合には国土地理院の承認を必要としません". [DR-RL-02]
- Nothing read on GSI's pages lists issued approvals, their holders or their scopes; the 承認申請 flow is applicant-specific (online 測量成果ワンストップサービス or mail). Who holds 令7関公第296号 is not stated in any text read; the PLATEAU lineage names the creator as 株式会社パスコ and the converter as PLATEAU CMS (repo record of the origin page). [DR-RL-01, DR-RL-02; docs/gis/rights/plateau-13116-related.json `origin`]
- GSI's June 2025 ガイドライン (地理空間情報の二次利用促進に関するガイドライン(測量成果等編)) is a full PDF (/common/000270912.pdf, summary /common/000270917.pdf). The landing page only says users are obliged to obtain 複製・使用承認 for some uses; the PDF body was **not read**. [DR-RL-05]
- PLATEAU's own text: the Site Policy §3(2) says "一部のコンテンツには、個別法令により利用に制約がある場合があります" and points to the 測量マニュアル; it names no 国土地理院 approval and no approval-number display. It requires 出典 and a separate 加工 notice. [DR-RL-06]
- PLATEAU FAQ: "手続き不要です。" for using the 3D city model data, with CC BY 4.0 and similar open licences; the FAQ does not mention 測量法, 国土地理院 or 道路. [DR-RL-07]
- PLATEAU 測量マニュアル ver04 (2025-04-02): 3D city models built from survey results require 測量法 procedures by the **creator**; 第30条 is an obligation on a person who intends to conduct a 基本測量以外の測量 using 基本測量成果. It says nothing read about downstream data users or 承認番号 display. [DR-RL-08]
- Net: **no public text read says that a third party redistributing derived data needs, or does not need, its own approval**; Q1-24 gives the general rule (holder's permission, plus a possible application for 複製承認 products). The 令7関公第296号 product type is recorded as 使用 in the repo lineage; its holder, scope and any condition remain **UNKNOWN**.

### 3.2 R1 Ikebukuro: CRS, spec version, terms (rank 15; IK-06)

- Dataset page `nwd_ikebukuro`: description 「国土交通省が整備した、池袋駅周辺の歩行空間ネットワークデータです。」; names the spec 「歩行空間ネットワークデータ整備仕様（2024年7月）」; 最終更新日 2019/01/28; CKAN created 2025-09-08, modified 2025-10-28; 4 resources (link/node, CSV and GeoJSON); **no CRS, no EPSG, no data-creation date**. [DR-RL-09]
- Spec 2024-07 §2.2: 「本仕様で扱うデータの座標系は、世界測地系緯度経度座標である測地成果2011（JGD2011）とする。」 Spec 2018-03 §2.2 says the same. Neither gives an EPSG code or an axis order, and neither says anything about GeoJSON `crs` members. Both mention WGS84 only as another 世界測地系. [DR-RL-11, DR-RL-12; verified in extracted text]
- The 新旧比較表 (2018.3 vs 2024.7) has **no coordinate-system row**; it lists the 2024.7 additions: ランク区分 (rank), ランク設定方法 (r_method), リンク作成・更新日 (maint date), and node 標高値 (elevation). [DR-RL-11]
- Spec 2024-07 states that data built to the 2018-03 spec corresponds in use to its layer-2 data. It has no sentence mapping a particular dataset to a spec edition. [DR-RL-11]
- Spec landing page labels the 2018-03 document 【旧仕様】 and the 2024-07 document 【新仕様】; no page update date; no text on 測地系 and no text on how older data relates to the new edition. [DR-RL-13]
- Which spec applies to the 2019-01-28 content: **no public text says**. What the public text supports: the dataset page cites 2024-07; the files carry fields that the public 新旧比較表 lists as 2024.7 additions (per the repo's recorded header observation, `docs/gis/research/network-codes-and-coverage.md`). That is consistent with a 2024-07 layout applied in 2025 to 2019 content, and says nothing about the survey date or the rank method. [DR-RL-09, DR-RL-11]
- Portal terms: the ほこナビDP has its **own** 利用規約 page (set 令和7年9月30日): content "準拠した利用条件（PDL1.0）", compatible with CC BY 4.0, 出典 required with the example 「出典：歩行空間ナビゲーションデータプラットフォームオープンデータサイト（当該ページのURL）」, a separate 加工 notice, and no representation as government-made. The page does **not** mention the 国土交通省ウェブサイト利用規約. Some content may be outside the rules, per a separate 「公共データ利用規約（第1.0版）に関する重要情報」 document (not read). [DR-RL-10]
- CKAN: `license_id` pdl-jp-1.0, `license_title` 公共データ利用規約(第1.0版）, `license_url` digital.go.jp PDL 1.0 page; each of the 4 resources has `license: null` (no per-resource licence, no description, no per-resource dates beyond created/modified 2025-09-08). [DR-RL-09, verified in raw JSON]
- Correction candidate for repo wording: records that say "PDL 1.0 via MLIT site terms" and bind a supporting document `https://www.mlit.go.jp/link.html` describe the MLIT website terms page, which is not the ほこナビDP terms page; the portal's own page is DR-RL-10. The MLIT page's text read says some content is under "別の利用ルール". [DR-RL-22, DR-RL-10]

### 3.3 PLATEAU catalog API vs CKAN-listed ZIP (rank 16; IK-01, SJ-01)

- Official documentation of the 配信サービス (docs.plateauview.mlit.go.jp, "PLATEAU 3D都市モデル配信サービスの公式ドキュメント"): the CityGML API page says the service can use CityGML "G空間情報センター において公開している都市の CityGML データを利用可能です"; the `url` field is "PLATEAU CMS 上の zip ファイル URL"; `gspatialjp_dataset_url` is the G空間 dataset page; `gspatialjp_files` lists "G空間情報センターで公開しているファイル" filtered by `spec`. [DR-RL-15, verified in raw page text]
- The same page, as a note: 「データカタログは G空間情報センターより先に新しいデータへ差し替わることがあります。そのため kind が citygml のファイルは、url の zip ファイルと異なる（古い）ことがあります。」 and "最新のデータカタログと同じ CityGML が必要な場合は url を使用してください". [DR-RL-15, verified]
- The 3D Tiles page says "G空間情報センターの更新はデータカタログより遅れることがあるため … 内容が異なる場合があります". [DR-RL-15, verified]
- The docs say the data is updated yearly (「PLATEAU の都市データは毎年更新され」), that the CMS `url` path "変わる場合があります", and recommend the stable `composite_url` (`/datacatalog/citygml/{cityCode}-{year|latest}/citygml.zip`, a redirect). The API is 「試験運用中」, with no guarantee of service period or level, and responses may change without notice. [DR-RL-15]
- The docs read (API index, CityGML, 3D Tiles, explorer pages) state **no licence, no 利用規約 and no attribution rule** for the API files; the only credit is the footer 「© 2026 Project PLATEAU」. They do not use the words CKAN or "identity"/"same file". [DR-RL-15]
- Live API metadata (2026-10-22): for 13116, catalog `url` = `…/assets/cc/d90677-ae87-4718-8899-f6131004cfa5/13116_toshima-ku_pref_2025_citygml_1_op.zip`, and the per-file `ubld` URL used by the repo sits under that same path (`…_citygml_1_op/udx/ubld/…`); `composite_url` `…/13116-2025/citygml.zip` answers HTTP 302 to that same asset. `gspatialjp_files[kind=citygml]` points to a **different asset** `…/assets/32/d726d2-f749-431e-9c0e-f7f9fad2cd3a/…` with the same filename, and that asset is what the CKAN package lists as 「CityGML（v5）」. Same pattern for 13104 (`84/48ebed…` vs `db/2866b9…`). The 3D Tiles/MVT ZIP and the `related` ZIP URLs are identical in both listings. [DR-RL-16, DR-RL-17]
- HEAD headers (no download), 13116: catalog asset 1,175,380,883 B, Last-Modified 2026-03-27 01:01:59 GMT; CKAN-listed asset 1,175,377,232 B, Last-Modified 2026-03-16 05:25:17 GMT. 13104: catalog asset 772,891,910 B, 2026-03-27 00:28:16 GMT; CKAN-listed asset 772,888,884 B, 2026-03-16 01:10:14 GMT. The catalog `file_size` field for 13116 reads 1,175,380,900 (17 B off the served length). These are metadata observations; **byte-equality of members was not tested**. [DR-RL-16, DR-RL-18]
- The CKAN package `plateau-13116-toshima-ku-2025`: created 2026-03-16, modified 2026-04-06, `license_id` plateau, `license_title` 「PLATEAU Site Policy 「３．著作権について」に拠る」, resource `license` null for all resources, no version field; its 「データ目録（v5）」 resource lists the CityGML ZIP's contents (index map, codelists, metadata, schemas, specification, `udx/…/ubld`), i.e. `ubld` is a member of the **CKAN-listed** ZIP by its own catalogue text. The note "最新版データは、V5です" and the v-numbering rule are in the package notes. [DR-RL-17, verified in raw JSON]
- The package notes say the data may be used freely including commercially ("商用利用も含め、どなたでも無償で自由にご利用いただけます"); this is dataset-level text and is not specific to files delivered by the API. [DR-RL-17]
- Net: official text confirms **two publication paths that can diverge and a catalog that can run ahead**; it does not state that the API files are identical to, a re-publication of, or licence-covered by the CKAN release. Licence coverage for API-delivered files is **UNKNOWN in public text**; the embedded metadata clause "Licensed under CC BY 4.0" (repo record) is still the only acquired text for the CC BY label.

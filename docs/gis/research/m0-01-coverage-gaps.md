# M0-01 coverage gap list: public data, rights and downloads for Ikebukuro and Shinjuku

Issue [#1](https://github.com/nurockplayer/gteki/issues/1) (M0-01) · Lane D · written 2026-10-22 · read-only research, no download, no `gis` command, no code change.

**Basis.** Main `f8ce063` (the PR #146 base; this branch adds only this file and one HANDOFF bullet) plus the open Lane D PRs read with `gh pr view` / `gh pr diff`, re-pinned 2026-10-22 to their current heads: #115 (`a43da2ec3e94`, draft: Shinjuku street context), #117 (`fabdce49d4ab`: Owner rights answers), #127 (`cd313a623497`: one E27 rights statement), #128 (`8f990719c023`: no source field values in POI reports), #138 (`8e3770d18d6f`: facts-only credit wording record) and #147 (`caeded7ef2b8`: classify non-POI source literals, #129, stacked on #128). Where a cell depends on a PR that is not merged, it says so (`PR#n`); **every cell without a `PR#n` tag is true on main**, and the status counts below are the main-state counts (the one row whose status changes if #115 merges is SJ-02). On main, `docs/gis/real-run.json` is valid; both #115 and #128 add an `invalidated` block to it, so a fresh full real run is needed after they merge (a process dependency, not a data gap).

**What this file is not.** It adds no rights clearance, accepts no geometry as the real station and calls no route navigable. Every normalized record stays `UNVERIFIED`, every GLB `NOT_FOR_ROUTING`, every candidate graph `routable: false` ([HANDOFF](../HANDOFF.md)). No station has a whole-station LOD4 interior in any acquired file; the only underground-building (`ubld`) files acquired are one Ikebukuro B1 passage file and one Shinjuku underground file, both called LOD4 by the API/metadata only (the inventories do not tabulate LOD per geometry), with coverage stated below.

**Public-repo rule.** After #128, committed GIS reports carry no source field values. This file therefore gives counts, hashes and source ids only, never shop names, hours, addresses or URLs from S10, S03 or the `related` layers. PR#147 extends the same rule to non-POI literals (classification in `rights/non-poi-literals.md` on that branch); this file quotes no such literal beyond the credit sentences the Owner fixed.

## Reading rules

**Status** (one per matrix row; it describes the best candidate for that row, and coverage and uncertainty are written separately in the last column):

| Status | Meaning here |
| --- | --- |
| VERIFIED | Bytes hashed, contents inspected into committed receipts, and the stated scope is closed (what the file holds and what it lacks are both recorded). Never means current-world accuracy or routability. |
| PARTIAL | Acquired and inspected, and a usable subset exists (rights settled or Owner-accepted for that subset), but coverage, CRS, currency or part of the rights are still open. |
| UNVERIFIED | No usable subset established: dossier-only (not acquired), acquired but unread, or a gating axis (rights, CRS, transform) is UNKNOWN for the whole candidate. Includes explicit no-data findings. |
| RESTRICTED | Rights bar the intended use for the whole candidate (reference-only, non-commercial, explicit refusal). |

**Ids.** Matrix rows are `IK-nn` (Ikebukuro) and `SJ-nn` (Shinjuku). Dossier card ids are always written `DOS:` + id (for example `DOS:S02`, `DOS:G5`, `DOS:I-06`) so they cannot be read as rows; Lane D source ids (`tokyo-s03-zip`, `tokyo-s10-*`) are written in full or as "S03" / "S10" in prose.

**Evidence key** (all paths are under `docs/gis/` unless stated; a cell cites the file and the field or sha that carries the claim):

| Tag | Meaning |
| --- | --- |
| `ACQ:<id>` | `acquisitions/<id>.json`, fields `bytes`, `sha256` |
| `INV:` / `CNV:` / `CTX:` / `NET:` / `OVL:` / `GAP:` | `inventory/` / `conversions/` / `context/` / `networks/` / `overlap/` / `gaps/` |
| `RGT:` / `POI:` / `CRS:` / `VIN:` / `DEC:` | `rights/` / `poi/` / `crs/` / `vintages/` / `decisions/` |
| `SRC:<id>` | `tools/gis/sources/sources.yaml`, fields `license_name`, `publish_gate`, `content_year` |
| `STN:` | `stations/<station>/gteki/station.json` or the named station file (a station-lane product, not an acquired public source) |
| `DOS:<card>` | `docs/research/GTEki_Public_Data_Research_2026-10-20.md` evidence card (dossier-only ids such as `DOS:S02`, `DOS:G5`, `DOS:I-06` are not in `SRC` and were not acquired) |
| `HANDOFF` | `docs/gis/HANDOFF.md` section named in the cell |
| `Q1`..`Q12` | Owner rights answers, [#39 comment 6324726321](https://github.com/nurockplayer/gteki/issues/39#issuecomment-6324726321); recorded in `DEC:2026-10-22-owner-rights-answers.md` (PR#117, not on main yet) |

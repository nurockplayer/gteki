# GTEki GIS data factory

An isolated TypeScript/ESM package for acquiring, inspecting and converting the bounded sources in Issue #10. Requires Node 26 and pnpm. All implementation and reports stay under `tools/gis/` and `docs/gis/`; the station and shared-core packages are not inputs or outputs of this lane.

Every normalized object is **UNVERIFIED**. Candidate graphs have `routable: false`; GLBs have `navigation_use: NOT_FOR_ROUTING` and `geometry_status: UNVERIFIED_RAW_CONVERSION`. File inspection, codelist labels and successful conversion do not establish public access, current conditions, floor alignment, accessibility or a passenger route. Source-native floor labels remain separate, and missing heights are never derived from a floor name.

## Install and checks

```sh
pnpm --dir tools/gis install
pnpm --dir tools/gis install --frozen-lockfile  # use in CI
pnpm --dir tools/gis typecheck
pnpm --dir tools/gis test
pnpm --dir tools/gis test:real
```

Run package commands sequentially. Concurrent pnpm 12 invocations were observed relinking the same `node_modules` during validation; the serial validation driver avoids that contention:

```sh
pnpm --dir tools/gis exec tsx src/validate.ts
```

It records frozen install, typecheck, synthetic tests, optional real tests and offline verification in `docs/gis/validation.json`, with full logs in the store. Offline verification preserves original HTTP acquisition timestamps and writes a separate latest offline-check receipt.

The package has its own `pnpm-workspace.yaml`, `package.json` and lockfile. No root package files are needed. There are no project lifecycle install scripts; the sole permitted dependency build is esbuild, used by tsx/Vitest. Exact versions are pinned. Runtime libraries are saxes (streaming XML with DTD rejection), yauzl (bounded ZIP reads), proj4 (explicit horizontal projection), earcut (polygons and holes), gltf-transform/core (GLB writing/readback), csv-parse (CSV syntax) and yaml (auditable source manifest). Node built-ins handle HTTP, hashes, CLI arguments, encoding and files. No Python dependencies or external archive executables are used. Optional real codebook tests require Poppler's `pdftotext` on `PATH` (or its path in `GTEKI_GIS_PDFTOTEXT`), invoked locally with `-raw`; no PDF content is fetched by the tests.

Default geometry/network tests use hand-written, clearly marked SYNTHETIC fixtures. The separate GSI control fixture records the two official calculator responses supplied by the lead; tests never fetch them. The optional real suite verifies every stored acquisition against its recorded SHA-256, checks each transcribed label against normalized PDF text, checks deterministic inventory bytes twice, and writes a bounded conversion to the external store. Without the complete source store, that suite is explicitly skipped.

## Store and source records

`GTEKI_GIS_STORE` selects the external store; the default is `~/.gteki/gis-store`.

```text
<store>/raw/<sha256>/<filename>          exact downloaded bytes, including catalog JSON
<store>/tmp/                           transient streaming downloads
<store>/out/*.glb                       real-data geometry
<store>/out/*.provenance.json           complete geometry provenance
<store>/out/*.candidate-graph.json      unverified source graph candidates
<store>/out/*inventory-detail.json      every semantic gml:id and its full metadata
<store>/out/run-logs/                   actual CLI stdout/stderr by run
```

Acquisition records contain store-relative paths. A store hash is rechecked before inspection or conversion. The git commit field identifies the checkout base; this implementation is deliberately left uncommitted for the lead, so that commit alone is not a snapshot of the new tool. Current run and validation receipts record a digest of source code, manifest, codebooks, frames, tests/fixtures and package configuration. Conversion identity includes frame contents, filters, semantic dictionary inputs and tool identity; dictionary archive/member hashes are retained in inventories and sidecars. A different dictionary, tool or frame preserves a distinct conversion path.

The checked-in manifest has exactly 55 bounded sources: the live PLATEAU catalog; each city's single underground GML, metadata, codelists and schemas; two Oedo-Shinjuku GeoJSON ZIPs; the Ikebukuro node/link CSV and GeoJSON pairs; three MLIT walking-network specification PDFs (2018-03, 2024-07, comparison); and the latest second-mesh 533945 ubld catalog. The spec landing page, MLIT site terms and R1 CKAN metadata are bounded supporting documents acquired by the same command and hashed inside the parent acquisition records. The first eleven Lane D entries add two S10 CSVs, S03 ZIP/spec/reference, their two Tokyo catalog snapshots, two PLATEAU related ZIPs and two G空間 CKAN snapshots. One vintage entry adds the G空間 CKAN snapshot of the 2023 新宿区 package (`plateau-13104-package-2023`, content year 2023, rights unknown, evidence only; see `inspect-vintages`). Fifteen integration entries add the fixed read-only PLATEAU GraphQL POST and 14 direct GeoJSON identity inputs. Origin product pages, current/old KSJ terms, four GSI pages, PLATEAU policy, PDL 1.0 and CC BY 4.0 Japanese legal code are hashed supporting snapshots. The POST acquisition records the exact UTF-8 body and its SHA-256. GET streaming, hashes and size checks are unchanged. Both Node fetch (manual mode) and curl (config disabled, no location following) enforce a zero-hop redirect budget: every HTTP 3xx fails with status and Location, even for captured HTTP errors. Declare an expected final URL in the manifest rather than following a remote redirect. S03 ZIP/spec/reference explicitly declare their final /documents/d/toshiseibi URLs. Their legacy catalog URLs and prior acquisition SHA-256 values are retained in catalog_resource_url/catalog_resource_sha256; rights coverage requires matching bytes. GSI supporting documents explicitly select curl because that server rejects the Node TLS handshake; certificate verification stays enabled. No full-city ZIP, tiles, imagery, operator map or scraped graph is acquired. Catalog-dependent resources are resolved from a fresh catalog response at acquisition time. Both the response SHA and the exact JSON pointer are recorded. Expected dossier URLs are cross-checks, not resource-resolution authority. Downloads are sequential, with no more than two retries and bounded backoff. Size mismatch is recorded and causes non-zero exit. Offline mode makes no HTTP requests. Nine street-level context entries (#39) add the bldg/tran catalog snapshot and eight PLATEAU bldg/tran mesh files (see "Street-level context (#39)"). One KSJ entry (`ksj-n02-2025`) adds the N02-2025 railway ZIP with its product page and KSJ terms snapshots (see "Context overlay").

The ignore file is a safety net, not a destination: never put downloaded bytes, real GLBs or raw archives anywhere in the repository. Only manual synthetic XML/CSV/GeoJSON fixtures belong in tests.

```sh
pnpm --dir tools/gis gis sources
pnpm --dir tools/gis gis acquire --all
pnpm --dir tools/gis gis acquire plateau-13116-ubld-53394576
pnpm --dir tools/gis gis acquire --all --offline
pnpm --dir tools/gis gis inspect-citygml plateau-13116-ubld-53394576
pnpm --dir tools/gis gis inspect-citygml plateau-13104-ubld-53394536
pnpm --dir tools/gis gis frame-from-envelope plateau-13116-ubld-53394576 ikebukuro-plateau-ubld-v0
pnpm --dir tools/gis gis crs-roundtrip ikebukuro-plateau-ubld-v0
pnpm --dir tools/gis gis citygml-to-glb plateau-13116-ubld-53394576 --frame ikebukuro-plateau-ubld-v0 --max-polygons 50
pnpm --dir tools/gis gis citygml-to-glb plateau-13116-ubld-53394576 --frame ikebukuro-plateau-ubld-v0 --bbox-local=-20,-20,20,20
pnpm --dir tools/gis gis citygml-to-glb plateau-13116-ubld-53394576 --frame ikebukuro-plateau-ubld-v0 --ids SOURCE_ROOM_ID
pnpm --dir tools/gis gis station-frame ikebukuro
pnpm --dir tools/gis gis context-glb ikebukuro --radius 250
pnpm --dir tools/gis gis inspect-network hokonavi-ikebukuro-walk-node-csv
pnpm --dir tools/gis gis inspect-network hokonavi-ikebukuro-walk-node-geojson
pnpm --dir tools/gis gis inspect-network hokonavi-oedo-shinjuku-network-geojson
pnpm --dir tools/gis gis inspect-network hokonavi-oedo-shinjuku-stationmap-geojson
pnpm --dir tools/gis gis overlap
pnpm --dir tools/gis gis gap-packet
```

`--ids` selects literal semantic IDs and their XML descendants, including source doors and surfaces. It does not create relationships from group membership, proximity, names or a shared floor label. `--bbox-local` requires four nonblank finite coordinates and selects whole polygons whose EN bounds intersect the rectangle; it does not clip or invent boundary geometry. The conversion API also checks the exact array length. `--max-polygons` caps selected polygons considered in source order and records excluded counts. There is no collision-proxy generator, snapping, floor-height inference or source-to-source graph join.

CityGML XML is streamed without a DOM. DTDs and external entities are rejected. ZIP members are read in-process; absolute paths, parent segments, encrypted entries, symlinks and excessive expanded sizes are rejected. Element classification uses namespace URI and local name; qualified spelling is retained as provenance. Anonymous semantic objects retain their own boundary and unknown source identity, so their metadata cannot migrate into a parent. Polygon metadata cannot become room metadata. Namespace/schema strings are recorded, never fetched or executed. Function labels come only from the actual matching codeSpace file; unresolved codes have a null label. A single declared CityModel envelope CRS is used explicitly for coordinates that omit a local CRS, and that interpretation is recorded; conflicting, unsupported or missing coordinate context fails.

A category such as “stairs and ramps” is reported as that combined source category, with individual facility types still UNKNOWN. Likewise, `bldg:Door` counts describe source semantic objects, not a count of physical doors; individual versus aggregate physical representation remains UNKNOWN unless separately evidenced.

CSV decoding first validates UTF-8, then Shift_JIS; the selected encoding is recorded. Mapping uses literal supported headers and preserves all raw attributes. GeoJSON with no `crs` reports the RFC 7946 longitude/latitude default as an assumption. Topology statistics use only source link endpoints. Coordinate gaps, duplicate IDs and absent geometry prevent conclusive endpoint comparisons; they do not trigger repairs. Station-map files produce layer inventories only.

GeoJSON features share an explicit node/link/unknown classification between inspection and export. Unsupported or conflicting evidence stays in `other_features`; a polygon or unidentified null geometry does not become an edge. Literal floor labels use explicit forms or dedicated source fields; generic descriptions such as 階段室 and 地下通路 remain UNKNOWN. Namespace-qualified GML mathematical topology is observed separately from renderable objects and never establishes navigable connectivity.

`overlap` reads the current CityGML envelope and Hokonavi layer inventories. It retains each source bbox/CRS, validates geographic ranges in the declared axis order, compares the horizontal JGD2011 geographic rectangles for intersection/disjointness, and projects bbox boundaries to EPSG:6677 to estimate their minimum separation. Invalid coordinates or non-finite projection results stay UNKNOWN; axes are never guessed. Each edge is sampled into 32 line segments; the reported metric distance is a numerical bbox-boundary approximation, not a feature distance. Projected axis-aligned envelopes are included as context. R1 alone uses spec-based EPSG:6668 inference, and its layers and pair metrics carry `CONDITIONAL_ON_INFERRED_CRS`. Other CSV sources retain UNKNOWN CRS. Bbox overlap never establishes shared floors, matching features or connectivity. The gap packets incorporate computed coverage HOLD items.

## Coordinates and geometry

Source EPSG:6697 is serialized latitude, longitude, orthometric TP height. The tool rejects a different CRS, a missing third ordinate or latitude/longitude outside Japan. EPSG:6677 is defined explicitly as Japan Plane Rectangular CS IX, GRS80, latitude of origin 36°, longitude of origin 139°50′, scale 0.9999, false East/North zero. Local coordinates subtract the explicit rounded projected envelope-centre origin. This is an arbitrary processing origin, **not a surveyed station reference point**. Heights remain orthometric; no geoid/ellipsoid conversion occurs. glTF maps East/Up/−North to x/y/z, in metres, right-handed and Y-up.

CRS tests cover the parameter origin, inverse roundtrips and two independent GSI JGD2011 zone IX numerical controls supplied by the lead (retrieved 2026-10-20). The [Ikebukuro control](https://vldb.gsi.go.jp/sokuchi/surveycalc/surveycalc/bl2xy.pl?outputType=json&refFrame=2&zone=9&latitude=35.729710&longitude=139.711376) and [Shinjuku control](https://vldb.gsi.go.jp/sokuchi/surveycalc/surveycalc/bl2xy.pl?outputType=json&refFrame=2&zone=9&latitude=35.692857&longitude=139.700825) are recorded in `test/fixtures/gsi-bl2xy-controls.json`; GSI publicX is Northing and publicY is Easting. Tests require each axis within 0.0005 m without network calls. These projection controls do not validate station alignment or source currency.

Two streaming SAX passes collect referenced polygon targets and then inspect definitions and uses. Surface orientation signs compose; unsupported or missing targets are reported. Inventory `polygon_count` counts inline definitions plus resolved uses, while `polygon_definition_count` counts definitions once. Per-object records separate inline definitions, resolved uses and unique definition IDs. Room selection counts unique definitions in its source subtree.

Conversion projects each polygon onto its Newell plane, triangulates holes, retains original 3D vertices with the source-use orientation, and counts skipped degenerate/invalid polygons. Boundary/opening representations keep their own orientation. When a selected boundary/opening already represents a polygon, its duplicate Room solid reference is retained in provenance instead of drawing a second coincident shell; a solid use without a selected boundary is converted with its own sign. Per-object sidecars record the use, context, orientation and disposition. Each retained semantic object has native identity and provenance in node extras; an unidentified object has a processing key and null native identity with UNKNOWN status. Meshes use neutral untextured surface-class materials. The resulting GLB is read back to compare semantic node and triangle counts and local bounds within 1 mm. This is a serialization/conversion check, not a visual, collision or navigation acceptance test.

## Reproduce the complete real run

Run these commands sequentially (the validation driver runs frozen installation, typecheck, default tests, real tests and offline acquisition verification in that order):

```sh
pnpm --dir tools/gis install --frozen-lockfile
pnpm --dir tools/gis typecheck
pnpm --dir tools/gis test
pnpm --dir tools/gis gis acquire --all
pnpm --dir tools/gis exec tsx src/real-run.ts
pnpm --dir tools/gis exec tsx src/validate.ts
pnpm --dir tools/gis exec tsx src/summarize.ts
```

The runner calls the public CLI in the requested order: acquisition; both GML inspections; frame creation/roundtrips; the smallest positive-polygon Room subtree and a full conversion for each city; R1 CSV and GeoJSON pair / S01 inspections; bbox overlap; all five POI/archive inspections; resource rights and research tables; gap packets. Each invocation records its command, exit code, elapsed time and external log pointer. Selection evidence is computed from the real feature tree. Any failed CLI invocation is recorded and stops the runner immediately; derived reports are not refreshed after failed prerequisites. Full-file memory/time evidence is emitted with each successful conversion. The current receipts are `docs/gis/real-run.json` and `docs/gis/validation.json`; superseded receipts are archived under `docs/gis/history/`.

## Rights, report size and handoff

PLATEAU GML is recorded as CC BY 4.0 on the dossier's metadata evidence; preserve attribution, license link, source/version and modification notice. The sidecar embeds the source manifest and acquisition record. Hokonavi is recorded as PDL 1.0, subject to attribution, modification notice and third-party exclusions. S01's stated availability deadline is 2027-03-12; this is a source availability date, not an invented revocation of compliant derivatives. Codelist/schema/metadata archive rights stay unknown unless evidence is separately established. No report grants public-product or redistributable-asset approval.

The brief asks for every feature in a Git inventory while also imposing a small-metadata-only Git boundary. Full feature inventories occupy tens of megabytes. To honor that boundary, the complete every-feature tree and semantic evidence IDs live in the external store. The committed inventory holds counts, namespaces, envelope, semantic summaries and a hashed detail pointer. This is the intentional report-placement deviation; no source records are discarded. The lead can audit the detailed JSON locally or regenerate it from the hashes.

See `docs/gis/README.md`, the generated summary, real-run receipts and per-station gap packets. Neither a source file's existence nor an ABSENT_IN_FILE result proves anything about an omitted or currently changed station area. Both stations remain HOLD for passenger-routing claims until the station lead obtains the missing current-world and operator evidence.

## Blender import check (optional)

`scripts/blender_import_check.py` is a headless check that a converted GLB imports into Blender with the expected local frame. It needs Blender 4.x/5.x, installed via Homebrew:

```bash
blender -b --factory-startup -P tools/gis/scripts/blender_import_check.py -- \
  "$GTEKI_GIS_STORE/out/<run_id>.glb" docs/gis/conversions/<run_id>.json /path/outside/repo/<name>
```

After glTF import, Blender is Z-up: x = East, y = North, z = Up. The script compares the imported world bbox with the recorded `bbox_local_ENU`, using a 1 mm tolerance. It writes `<name>.import-check.json` and renders top and perspective Workbench images for review. Renders inherit the PLATEAU CC BY 4.0 attribution obligation and are kept out of Git. Committed results are in `docs/gis/evidence/`.

For a cached replay, use `pnpm --config.offline=true --dir tools/gis exec tsx src/real-run.ts` (then `validate.ts` and `summarize.ts`) with `GTEKI_GIS_OFFLINE=1` in the environment. The pnpm option prevents automatic dependency downloads before the driver starts; the environment switch makes the drivers check cached acquisitions and run frozen installation offline. Missing cached inputs fail the run.

## Versioned walking-network codes and coverage

`codebooks/mlit-walk-network-{2018-03,2024-07}.json` are fingerprinted literal transcriptions, with source SHA, table and printed page per field. `attribute_decoding` reports observed code distributions, per-version undefined codes and label counts, overall compatibility and an always-UNKNOWN applicable version. Membership does not test required-column completeness or current conditions. Raw candidate attributes stay verbatim; decoding appears only in reports. The 2018 waterway code 2 has no label printed in table 3.2 (p15); its null label is explicitly MANUAL with a reason. Real tests normalize whitespace only and check all other labels against acquired PDF text. Intermediate weekday names are not supplied where only the 1–7 range is printed.

The 2024 rank cross-check reads each `r_method` digit independently. Field survey (digit 1) uses all table 3.3 intervals (p21): width 1→Z, 2→A, 3/4→S; slopes 1→S, 2→A, 3/4→B, 5/6→C, 7/8→Z; steps 1→S, 2→A, 3→B, 4→C, 5→Z; every 99→X. Mobility trace (digit 2) uses only red-underlined readings, as required on p20: width code 1→C; slope/step A/B/C use upper thresholds including zero, and their Z bounds remain supported. Width S/A/Z/X and slope/step S/X are `not_checkable` for trace: S's 0% / 0cm cells are black, not red-underlined on p21. Thus code-1 triplet CSS with method 222 has consistent width but not-checkable slope and step. A missing/blank/other method digit uses only supported survey/trace readings; zero slope/step retain S from survey and A/B/C from trace, with accepted membership reported as `method_unknown`. The check never repairs rank or establishes accessibility.

R1 CSV/GeoJSON comparison joins unique IDs, compares all shared fields, and compares CSV lon/lat with GeoJSON Point coordinates. Numeric representation differences are compared numerically without changing either raw value; blank and null both mean absent. CSV links contain no polyline, so geometry equality is UNKNOWN. GRS80 Vincenty length sums only supplied segments and compares literal distance with a 0.05 m rounding threshold plus 0.000001 m floating tolerance. The exact R1 data have 30 links beyond that threshold; the result is `NO_VERDICT`. Low residuals support lon/lat-degree and metre consistency under the stated assumption but cannot identify the datum. EPSG:6668 remains `INFERRED_FROM_SPEC`, citing §2.2 (2018 p5; 2024 p4); RFC 7946 is an assumption only, not evidence for JGD2011.

`overlap` also computes R1 node containment in the acquired PLATEAU geometry bbox by literal floor/in_out and intersection counts for supplied rt_struct 5/7 polylines. This is conditional bbox evidence only. JIS X 0410 codes use 40′×1° first meshes, 5′×7.5′ second meshes and 30″×45″ third meshes; tests include Tokyo Tower → 53393599 and nominal 53394536 bounds. The arithmetic follows the [Statistics Bureau regional-mesh explanation](https://www.stat.go.jp/data/mesh/gaiyou.html); this reference was not fetched in this lane under the network restriction. Closed bboxes include boundary-touching cells. Catalog coverage records latest files, nominal mesh bounds and computed geometry bboxes separately; nominal meshes never establish coverage. Older vintages remain UNKNOWN. See `docs/gis/research/network-codes-and-coverage.md` and generated gap packets for source hashes and findings.

`inspect-poi` records strict UTF-8/Shift_JIS decoding, headers/member names, populated/blank row counts, per-field blank/missing/type/distinct counts and `{ value_sha256, value_type, count }` distributions (no literal values), CRS declarations, native XY bboxes and geometry types. It preserves every literal field value (opening hours, locations, levels, names, URLs, descriptions) only in the hashed, git-ignored external detail report (`detail.store_path`). S03 legacy ZIP filenames are decoded as Shift_JIS; explicit-null CRS and nonstandard Path command tuples cannot become geographic positions. HERE source n1/n2 references are inventoried only, with zero exported edges and `routable:false`. Station relevance is conditional numeric bbox arithmetic against the existing PLATEAU/Hokonavi layer envelopes, never a floor, station membership or connection inference.

**No source values in Git (#124).** The repository is public and some POI sources carry no release permission (KSJ non-commercial P20/P13/N10; S03 promotional prose and linked content are UNKNOWN). Committed files under `docs/gis/**` therefore never contain a literal source field value from any POI source, cleared or not. Allowed: field names (schema keys), blank/missing/type/distinct counts, feature/entity counts, CRS and bbox statistics, station relevance, evidence ids, our derived statuses and short licence/terms quotes. Every distinct field value (and every root property) is committed only as `value_sha256` (SHA-256 of the UTF-8 value; non-string JSON values hash their JSON text, with `value_type` to keep `"1"` and `1` apart) plus `count`, ordered by count then hash and capped at five per field. The writer is `fieldStatistics` / `inventoryJson` in `src/poi.ts`; consumers (`gaps.ts`, `poi-research.ts`) read only the hashed form, and anything needing a literal must read the store detail report and still not commit it. Hashes of low-entropy values can be guessed by dictionary; that is accepted. Rewriting earlier history is an Owner decision recorded on #124. Guard it with the read-only `pnpm --dir tools/gis gis check-poi-literals` (set `GTEKI_GIS_STORE`): it extracts every free-text value from the store's `out/poi/*.json` details and fails (exit 1) if any appears verbatim or JSON-escaped anywhere under `docs/gis/**`. It also fails unless every committed `poi/*.json` report's `detail.store_path` exists in the store with matching `sha256` and `bytes` (`detail_problems`, reasons `missing` / `hash_mismatch`, naming the source), and when zero literals were scanned; stale or unreferenced details in `out/poi` are still scanned as extra inputs; generic words that coincide with our own text are exempt via `codebooks/poi-literal-allowlist.json`, only inside prose: a whole JSON value or key equal to an allowlisted term still fails unless it is one of the declared `structural_values` (our own enum values) or a credited MLIT specification label (class (a), Owner decision (ii)). Substring or paraphrase leakage is not detected. The synthetic tests are `test/poi-literals.test.ts` and `test/poi-rights.test.ts`. The rule text is also generated into `docs/gis/rights/README.md` by `rights-report`.

**Non-POI source literals (#129).** The same rule now covers the other sources, split by recorded rights and recorded decisions in [docs/gis/rights/non-poi-literals.md](../../docs/gis/rights/non-poi-literals.md) (generated by `gis literals-report`; terms quoted verbatim from `sources/sources.yaml`, nothing inferred). Class (a), kept with a credit: the two PLATEAU ubld files (CC BY 4.0: `gml:id`, `gml:name`), the four Hokonavi Ikebukuro sources (Owner decision (i), PR #147 comment 6330792563: attribution under the package-level PDL 1.0 notice, Ikebukuro only) and the MLIT specification labels (2018-03, 2024-07; the codebooks are public by Owner decision (ii), and director gteki-80 extended that to the report labels). The credit is a `credit` field in generated inventory, network and gap JSON, a `Credit:` line in their Markdown, and the sentences listed in the classification file; the MLIT credit names the specification, version, URL and snapshot SHA-256 from `docs/gis/acquisitions/`. Class (b), unclear or no-release (the PLATEAU codelists, rights `unknown`, and Hokonavi E27, Q11): committed `inventory/`, `networks/` and `gaps/` reports carry `{ value_sha256, value_type[, count] }` (`label_hash`, `function_label_hash`, `floor_label_value_hash_distribution`, `value_hash_distribution`, hashed identifier lists) and the verbatim report goes to the git-ignored store (`out/networks/<id>-<sha12>.network-detail.json`, referenced by a `detail` pointer with sha256 and bytes). Source codes (numeric, `(blank)`, `(unavailable)`, `(unknown)`, or a short ASCII token of at most three characters such as rank `SBS`) stay as codes; every other class (b) value, however short, is wording and is hashed. `gis check-literals` (alias `check-poi-literals`) reads the hash-verified store copies of every class (b) source and fails on a leak anywhere under `docs/gis` (whole JSON strings and keys are compared exactly, wording is found as an NFKC substring whatever its length, so `1階のみ`, `1階に` and `地下1階へ` are caught (Japanese particles are letters, so no word boundary is used); a short literal inside a longer known term, meaning class (a) wording, class (b) wording or an allowlisted term, is not counted, longest term first; only an MLIT specification label that is also a class (b) literal is deducted as public, and a word that Hokonavi E27 also owns stays guarded and fails the check), a missing or altered store copy or report detail, zero literals for a source, a network or inventory report whose source is not in the classification (`LITERAL_CLASSES`), a class (a) credit missing from the classification file, a class (a) credit that cannot be composed from the records (an MLIT acquisition record or its sha256 is missing: there is no fallback to the recorded attribution text), or a file that keeps class (a) values without the credit or a pointer to the classification file (an MLIT label of any length counts: a short one where it is data, a whole JSON value or key, table cell or list item, a long one anywhere). Allowlisted generic terms are exempt only inside our own prose; the sole whole-value exemptions are `structural_values` (our own enum values such as `road`, `unknown`, `stairs`), for POI values and class (b) alike, plus, for POI values only, the credited MLIT specification labels (class (b) deducts them as public instead). Every allowlist term has its reason in `justifications`. `gis scrub-literals <path...>` is a deterministic offline migration that replaces class (b) literals with `value_sha256:<hex>` in files no generator can rebuild without a real run (`history/**`, `real-data-summary.*`, prose quoting an identifier). It parses JSON and rewrites only whole values, keys and wording inside strings (never inside a known longer term), and refuses JSON that is not in the generators' 2-space form; the next real run writes the structured form. `tools/gis/codebooks/mlit-walk-network-*.json` are public and each carries a `source_note` (specification, version, URL, snapshot SHA-256, credit). **CI:** `check-literals` needs the private store (`~/.gteki/gis-store`), so it cannot run in CI and nothing on `main` enforces the leak scan by itself; run it on the developer host before a PR. The store-free tests in `test/literals.test.ts` check the committed reports for registered sources, credits and the current classification file. **Scope:** the scan reads `docs/gis/**` only. ## PLATEAU vintages, ZIP member identity and bbox/CRS hardening

```sh
pnpm --dir tools/gis gis acquire plateau-13104-package-2023
pnpm --dir tools/gis gis inspect-network hokonavi-oedo-shinjuku-network-geojson
pnpm --dir tools/gis gis inspect-network hokonavi-oedo-shinjuku-stationmap-geojson
pnpm --dir tools/gis gis inspect-vintages
```

`inspect-vintages` reads the two 2023 新宿区 CityGML archives listed in the hashed `plateau-13104-package-2023` CKAN snapshot by HTTP range. It fetches only the ZIP end record and central directory, then the selected `ubld` members whose mesh touches the E27 layers' meshes (closed intersection) or target mesh 53394525. Nothing is downloaded whole. The live fetcher keeps main's zero-hop redirect rule: it requests with `redirect: manual`, refuses every 3xx, requires the final URL to equal the package's URL, and accepts only the `assets.cms.plateau.reearth.io` origin. Archive identity is a strong ETag (sent as `If-Range`) plus a pinned final URL, `206` with matching `Content-Range` and total length on every range; weak or missing ETags fail before any byte is retained. Each selected member is checked for local-header/central-directory agreement, size and CRC32, and hashed with SHA-256. Range payloads, central directories and members are stored content-addressed in the external store; Git receives `docs/gis/vintages/shinjuku-2023.{json,md}` and the receipts in `docs/gis/acquisitions/vintages/`. All outputs are promoted together by `report-transaction.ts` and rolled back on any failure. Every finding is UNVERIFIED, `routable: false`, rights HOLD, licence UNKNOWN.

The report accepts the E27 network reports only when they carry the current tool fingerprint, the current acquisition hashes and complete lineage. A layer is compared only when its `crs` is a plain `{type: "name"}` geographic declaration, its bbox status is `COMPUTED` and valid, and no other declaration in the same report conflicts. Linked, malformed, null, assumed, conflicting or INCOMPLETE inputs (and a missing 2023 CityGML bbox) give UNKNOWN, never DISJOINT, and select no mesh.

`geo-bbox.ts` computes every GeoJSON bbox. Coordinate nesting is validated per geometry type, and traversal is bounded by 1,000,000 visits and 16 GeometryCollection levels. A malformed, unsupported or over-budget geometry, or a feature- or geometry-level `crs` override, withholds the whole bbox (`bbox: null`, `bbox_status: INCOMPLETE_*`). `inspect-network` and `inspect-poi` use it, and a link-type or otherwise non-`name` `crs` never selects an endpoint-distance method. An explicit `"crs": null` is UNKNOWN; only an absent member is the RFC 7946 assumption.

`readZip` entries now carry `name_bytes_hex` (the raw central-directory name bytes: the identity), `name_utf8_flag`, `name_cp437`, `name_utf8` and a labelled `name_cp932_candidate`, with `name_encoding_status` of `DECLARED_UTF8`, `DECLARED_UNICODE_PATH_EXTRA`, `ASCII_ONLY`, `CANDIDATE_CP932_UNDECLARED` or `UNDECLARED_UNRESOLVED`. `name` is unchanged: the specification decoding, or the caller-asserted `legacyFileNameEncoding` used for S03.

Vintage comparison gates (fix pass 1): a member's CityGML geometry coverage (`geometry_coverage`: resolved vs unresolved/unsupported references) is recorded, and INTERSECTS/DISJOINT require it to be complete, otherwise the row is UNKNOWN with an `unknown_reason`. Every declared network CRS name, geographic or not, is checked for disagreement (for example EPSG:6668 with EPSG:6677 in station-map members), so a conflicting report yields no usable layer. `verifyVintageEvidence` rejects a report whose `tool_input_sha256` is missing or differs from the current tool fingerprint.

Round 2: coverage also requires zero unconsumed coordinate-bearing GML elements (`geometry_coverage_gaps` in the CityGML inventory counts `pos`/`posList`/`coordinates`/`coord` outside a Polygon ring, for example `Ring/curveMember/LineString`; such shapes are counted, not parsed, so a bbox that omits them cannot yield DISJOINT). The vintage `input_sources` inherits each E27 network report's transitive inputs (walking-network specifications included), and `verifyVintageEvidence` re-runs `assertNetworkInspectionCurrent` on those reports and requires every one of those inputs, with matching hashes, in the vintage report.

## Street-level context (#39)

Visual-only PLATEAU surface buildings and roads around a station, in the **station frame**, for Lane G. Issue [#39](https://github.com/nurockplayer/gteki/issues/39); first pass is Ikebukuro. Everything is `UNVERIFIED` and `NOT_FOR_ROUTING`, gates stay `HOLD`/`CONDITIONAL`, and no rights clearance is added. Full status, open questions and wiring: `docs/gis/HANDOFF.md`, "Street-level context (#39)".

```sh
pnpm --dir tools/gis gis acquire plateau-catalog-bldg-tran-13116-13104 plateau-13116-bldg-53394576 plateau-13116-bldg-53394577 plateau-13116-tran-53394576 plateau-13116-tran-53394577
pnpm --dir tools/gis gis station-frame ikebukuro            # frames/ikebukuro-station-enu-v0.json (committed; rerun only if station.json origin changes)
pnpm --dir tools/gis gis context-glb ikebukuro                      # config defaults: R_origin 250, R_exit 120, merge kind, variant high
pnpm --dir tools/gis gis context-glb ikebukuro --variant low         # buildings LOD1 only
pnpm --dir tools/gis gis context-glb ikebukuro --merge tiles:150     # grid tiles per kind instead of one mesh per kind
pnpm --dir tools/gis gis context-glb ikebukuro --merge none          # one node per feature (debugging)
pnpm --dir tools/gis gis context-glb ikebukuro --variant low --kinds bldg   # buildings-only low GLB (phones)
pnpm --dir tools/gis gis context-glb ikebukuro --radius 250 --exit-radius 0   # origin disc only (no graph.json read)
```

Options: `--radius M` (R_origin), `--exit-radius M` (R_exit; 0 = no exit discs), `--merge none|kind|tiles:<size_m>` (default from the config, `kind`), `--variant high|low` (default `high`), `--kinds bldg,tran` (default from the config, else both; a non-empty subset), `--sources id,id` (replaces the config's source list; the mesh-coverage check still applies).

- **Sources:** `plateau-catalog-bldg-tran-13116-13104` plus `plateau-{13116,13104}-{bldg,tran}-<mesh>` (Ikebukuro `53394576`/`53394577`, Shinjuku `53394525`/`53394526`). `expected_bytes` above 128 MiB raises that source's download cap to exactly that size; all other sources keep the 128 MiB cap. The catalog `fileSize` is exact for `tran` but 0.3-0.5 % short for `bldg`, so the manifest declares the measured served size.
- **Frame:** `station-enu` (packages/geo `StationFrame`: ENU tangent plane on GRS80, `z = height - hM`). Created from `stations/<id>/gteki/station.json` (read-only, SHA-256 recorded); refused when `hM` is not a number or the CRS is not EPSG:6697 (Shinjuku). `citygml-to-glb --frame <station-enu frame>` works for any EPSG:6697 source; envelope frames keep their source-provenance check. Pinned to packages/geo by `test/fixtures/station-enu-vectors.json` (0/250/435 m, 1 mm).
- **Window = union of discs:** one disc of `R_origin` (250 m) at the station origin plus one disc of `R_exit` (120 m) around every node of `stations/<id>/gteki/graph.json` that the context config's `window.node_rule` marks as an exit connector (`node.kind` in `exit_kinds`) or a street-level node (`node.floorId` in `street_floor_ids`). Nothing is guessed: the rule is explicit config. Ikebukuro: `exit_kinds ["exit"]`, `street_floor_ids ["street"]`; the committed graph has 62 nodes, 20 of kind `exit`, all 20 on floor `street`, no other street-level node, so 21 discs. With `node_rule.exit_poi_connectors: true` (Ikebukuro) every graph node that `pois.json` names in `connectorNodeIds` of a POI whose `category` is `exit` also gets a disc: that adds exactly `x36f`, `x4f` and `x13f` (b1 stair feet of exit-36, exit-4, exit-13), so 23 nodes and 24 discs; other `stair_end` nodes do not. `pois.json` is read-only and its sha256 is recorded beside the graph's; the mesh coverage stays `53394576` + `53394577`. `graph.json` is read-only and its sha256 is recorded in the receipt and in every mesh's extras.
- **Selection:** a top-level `bldg:Building` / `tran:Road` is selected when its XY bbox (all vertices, every LOD) meets **any** disc (closed, exact bbox-disc distance); whole features, never cut. **LOD (variant high):** buildings LOD2 else LOD1 (never LOD0, never both); roads LOD3 only, because LOD1/LOD2 roads are flat at z=0 (excluded and counted; no ground height is invented). **Variant low:** buildings LOD1 only (a building without LOD1 is excluded and counted as `building_no_lod1_excluded_in_low_variant`); roads unchanged (LOD3), with building and road triangles reported separately (`totals.triangles_by_kind`) so roads can be dropped from low. Nothing is decimated or simplified.
- **Mesh coverage (fail closed):** before any source is read, the 3rd-level JIS X 0410 meshes (8 digits, 30" x 45" cells; `meshCode3`) that any disc touches (plus `window.mesh_margin_m`, 50 m for Ikebukuro, because served features straddle their cell edge by up to about 38 m) are computed from the cell geometry in the station frame. If a needed mesh has no bldg or no tran source in the config, or a configured needed source is not acquired, `context-glb` fails and names the meshes; it never clips silently. Configured sources for meshes the window does not touch are ignored and listed as `unused_sources`. The Ikebukuro window needs `53394576` and `53394577` (bldg and tran), all four already acquired; the next mesh (`53394586`) only matters beyond about 100 m of margin.
- **Kinds (`--kinds bldg|tran|bldg,tran`):** default from the station config's optional `kinds`, else both. Ikebukuro defaults to both kinds. **Roads ship as geometry only, under an Owner risk acceptance** (`docs/gis/decisions/2026-10-22-plateau-tran-geometry-risk-acceptance.md`, #39): the GSI approval 令7関公第296号 in the PLATEAU `tran` lineage is treated as attribute-scoped, no `tran` attribute is shipped (a test enforces this), and the UNKNOWN rights evidence is unchanged. `--kinds bldg` gives the buildings-only files. Deploy attribution, shown as-is wherever the context renders: 「出典：国土交通省 Project PLATEAU（3D都市モデル）を加工して作成」. An excluded kind's sources are never opened or scanned, its meshes are absent, and mesh coverage is checked only for the requested kinds. Receipt, run id, window and every mesh/node/scene extras record `kinds`; a subset adds a suffix to the run id (`...-low-kind-bldg-<digest>`), the full run keeps the old id shape. Refused: any value other than `bldg`/`tran`.
- **Merged output (`--merge`):** `kind` (default) writes one building mesh `ctx_bldg_all` and one road mesh `ctx_road_all`, one primitive and one material (`building`, `road_surface`) each, so 2 draw calls. `tiles:<size_m>` writes spatial grid tiles per kind, `ctx_bldg_t03_05` (column, row; grid anchored at the window bounding box floored to the tile size; a feature goes to the tile of its bbox centre, whole). `none` is the per-feature layout (`ctx_bldg_<gml_id>`, four per-class materials). Mesh and node extras carry `gteki_role "context"`, `navigation_use NOT_FOR_ROUTING`, `visual_only`, `source_ids` and `source_sha256s`, `frame_id`, `station_json_sha256`, `graph_sha256`, the window spec, `lod_used` counts, `merge`, `variant`. Provenance per feature lives in the sidecar and the receipt as a feature table (`gml_id, source_id, lod, mesh, tri_start, tri_count`); the readback fails the run unless the ranges cover every triangle of every merged mesh exactly once.
- **Two passes, bounded memory:** pass 1 keeps only gml:id, bbox and LOD facts per feature; pass 2 retains, converts and discards only the selected features. Textures are never read. `scanCityGml` and the ubld conversion are untouched (`test/ubld-regression.test.ts` pins their GLB bytes).
- **Tagging:** nodes `ctx_bldg_<gml_id>` / `ctx_road_<gml_id>` with `extras.gteki_role = "context"`, `navigation_use: "NOT_FOR_ROUTING"`, `visual_only: true`, source/frame/`station_json_sha256`/`lod_used` and the PLATEAU attribution. Node names never match an explorer role word; the readback fails the run otherwise.
- **Outputs:** GLB and `.provenance.json` in the store (`out/context-<station>-r<R>-x<R_exit>-<frame>-<variant>-<merge>-<digest>.glb`); receipt in `docs/gis/context/<run_id>.json` (kept out of `docs/gis/conversions/` so `real-run`/`summarize` ignore it).
- **Shinjuku** is blocked on its vertical anchor (`sources/context/shinjuku.json`, `status: BLOCKED`); `station-frame shinjuku` and `context-glb shinjuku` refuse.

### Running the real Ikebukuro context (memory-capped)

The real GMLs are 20-168 MB each (about 490 MB in total for the four Ikebukuro files). Do not run this on a shared host; use a container with a memory cap. Inside the container (repo mounted, `GTEKI_GIS_STORE` pointing at a store that already holds the four acquired sources):

```sh
pnpm --dir tools/gis install --frozen-lockfile
export NODE_OPTIONS=--max-old-space-size=768
pnpm --dir tools/gis gis context-glb ikebukuro --variant high   # merge kind: ctx_bldg_all + ctx_road_all
pnpm --dir tools/gis gis context-glb ikebukuro --variant low
pnpm --dir tools/gis gis context-glb ikebukuro --variant low --kinds bldg   # optional buildings-only low GLB; scans only the two bldg files
```

Run the two variants one after the other (not in parallel). Expected need per run: roughly 330-420 MB peak RSS and under a minute (each file is scanned twice at about 30 MB/s; the earlier 250 m disc run measured 327 MB RSS and 14.8 s in a `--memory 1g` container; the window selects about 1.3 times as many features, and merged meshes hold their vertex arrays until the end). Memory scales with the number of selected features, not with the file. A 1 GB `--memory` limit is generous. `context-glb` re-verifies each source's stored SHA-256 before use, so no separate `acquire --offline` is needed.

### Context overlay: station and railway lines (`context-overlay`)

Visual-only 2D lines from KSJ N02-2025 (`ksj-n02-2025`, CC BY 4.0, publish gate CONDITIONAL) in the station frame. `UNVERIFIED`, `gteki_role context`, `NOT_FOR_ROUTING`, never routable.

```sh
pnpm --dir tools/gis gis acquire ksj-n02-2025                        # 14.9 MB nationwide ZIP + product page + KSJ terms snapshots
pnpm --dir tools/gis gis context-overlay ikebukuro                   # window from sources/context/ikebukuro.json (R 250 m + exit discs)
pnpm --dir tools/gis gis context-overlay shinjuku --kinds railway    # origin disc 250 m; --kinds station|railway, --no-glb, --radius, --exit-radius
```

- **Input:** two members of the ZIP, named in the `overlay.layers` of `sources/context/<station>.json`: `N02-25_GML/UTF-8/N02-25_Station.geojson` (10,234 `LineString` features, so N02 stations are short lines, not points) and `N02-25_GML/UTF-8/N02-25_RailroadSection.geojson` (21,933 features). Only those two members are read. The ZIP also holds Shift-JIS and UTF-8 shapefiles, the JPGIS GML and the application schema; they are ignored.
- **CRS and axis order (read from the file, never assumed):** both GeoJSON files declare `urn:ogc:def:crs:EPSG::6668` (JGD2011 geographic) and list positions as `[longitude, latitude]`. The command classifies every vertex by the Japan ranges (longitude 122-154, latitude 24-46 are disjoint), fails on a missing or other CRS, on an ambiguous or out-of-range position, on mixed orders, and on any geometry other than `LineString` / `MultiLineString`. A file with `[lat, lon]` is also read correctly (tested).
- **Selection:** the context window of the station config (union of discs; `buildContextWindow`). A feature is selected when any segment of its projected polyline meets a closed disc (exact segment distance), and is kept whole. A degree box prefilter skips most of the nationwide file before projection.
- **Projection:** `stationLocal` for Ikebukuro (`ikebukuro-station-enu-v0`). Shinjuku has no station-enu frame (`origin.hM` null), so it uses `origin-only`: the horizontal ENU at the `station.json` origin, evaluated at height 0 (same x/y to well under a millimetre), no vertical anchor asserted.
- **z (per-station config, `overlay.z`; no DEM draping, no baked offset):** Ikebukuro constant 32.5, recorded as "render z = street floor renderElevationM" (the ordinal-0 floor of `stations/ikebukuro/gteki/station.json`; that floor has `elevationM` null and `elevationSource` unknown, so this is a render anchor and not a TP ground height). Shinjuku constant 0, recorded as "symbolic street z = 0 (no datum asserted)". The value is re-read from `station.json` on every run and a mismatch fails the run.
- **Properties kept:** `gteki_role`, `navigation_use`, `visual_only`, `kind` (`station` or `railway`), `source_id`, `source_sha256`, `feature_hash` (sha256 of the source feature as parsed) and `credit`. No name, code, operator, line, class or other N02 attribute is copied, and none is written to the GeoJSON, GLB extras, sidecar or receipt. A leak guard compares every output with the keys and string values of the selected features and fails the run on a hit. N02 has no underground versus at-grade field, so rail ribbons say nothing about track level.
- **Outputs:** private store `out/overlay-<station>-r<R>[-x<Rexit>]-<frame>[-kinds]-<digest>.geojson` (station-frame `[x east, y north, z]` metres), `.glb` (flat ribbons merged per kind: `ctx_rail_all` 1.5 m, `ctx_station_all` 3 m; two triangles per segment; read back and checked to 1 mm) and `.provenance.json`. Public receipt `docs/gis/context/overlay-<...>.json`: counts, member and feature-hash digests, bbox, credit, z basis, frame, source sha256, output hashes.
- **Credit (wherever the overlay renders):** 「出典：国土交通省国土数値情報ダウンロードサイト（https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html）を加工して作成」.
- **Cost:** about 1.3 s and 350 MB peak RSS per station on the host (the two GeoJSON members are parsed whole); run it under the shared test lock.
